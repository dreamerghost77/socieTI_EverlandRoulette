# 에버랜드 MT 추첨 시스템

15명의 참가자를 세 팀으로 나누고, 팀별 놀이기구와 미션을 정해 완성된 티켓으로 저장하는 정적 웹 앱입니다.

## 팀과 참가자

| 팀 | 난이도 | 인원 | 놀이기구 배정 |
| --- | --- | ---: | --- |
| 상 난이도 1팀 | 상 | 5명 무작위 추첨 | 상 난이도 목록에서 추첨 |
| 상 난이도 2팀 | 상 | 5명 무작위 추첨 | 상 난이도 목록에서 추첨 |
| 중 난이도 1팀 | 중 | BJ, MYJ, JT, KW, CYJ 사전 확정 | 중 난이도 목록에서 추첨 |

참가자는 `KMK`, `MJ`, `MH`, `BJ`, `SB`, `MYJ`, `PMK`, `SI`, `JT`, `KW`, `SH`, `HW`, `SW`, `CYJ`, `SM`입니다. `JW`는 명단에 포함하지 않습니다. 고정 팀의 다섯 명은 상 난이도 참가자 추첨에서 미리 제외되며, 나머지 열 명은 상 난이도 두 팀에 다섯 명씩 중복 없이 들어갑니다.

현재 프로젝트의 놀이기구 데이터와 효과를 사용합니다. 상 난이도 풀은 T 익스프레스와 허리케인, 중 난이도 풀은 아마존 익스프레스와 썬더폴스입니다. 같은 난이도에서 한 번 확정된 놀이기구는 다시 뽑히지 않습니다.

## 진행 순서

1. 팀의 난이도에 맞는 놀이기구를 원통형 룰렛과 기존 테마 연출로 공개합니다.
2. 상 난이도 팀은 이름 이니셜 원통과 성씨 카드를 사용해 참가자 다섯 명을 한 명씩 뽑고, 각 이니셜을 티켓 슬롯에 순서대로 기록합니다. 중 난이도 팀은 고정 명단을 보여주고 이름 추첨을 건너뜁니다.
3. 놀이기구별 스페셜 미션 한 개와 중복 없는 일반 미션 네 개를 카드 뒤집기 효과와 함께 뽑습니다.
4. 실제 사다리 연결 구조를 생성합니다. 세로선과 충돌하지 않는 가로선을 그린 뒤 구조를 투명하게 낮추고, 참가자를 누를 때마다 그 사람의 실제 경로만 네온으로 추적합니다. 지나간 다섯 경로는 각각 다른 색으로 남습니다.
5. 스페셜 미션에 도착한 참가자가 자동으로 팀장이 됩니다. 다섯 명의 결과가 모두 정해진 뒤 다음 팀으로 넘어갑니다.
6. 마지막 화면에서 완성 티켓 세 장을 각각 고해상도 PNG로 저장하거나, 세 PNG가 들어 있는 ZIP 파일 하나로 저장합니다.

## 미션 데이터와 안전

놀이기구별 스페셜 미션과 일반 미션 풀은 [event-data.js](event-data.js)에 분리되어 있습니다. 각 팀은 놀이기구에 맞는 스페셜 미션 한 개와 일반 미션 네 개를 받습니다. 일반 미션은 팀 안에서 중복되지 않습니다. 촬영은 팀원과 촬영 대상의 동의를 받고, 탑승구역이나 통행을 방해하지 않는 안전한 장소에서 진행하도록 작성했습니다.

## 추첨 상태와 사다리

놀이기구, 참가자, 미션, 사다리 연결, 확정된 경로와 팀장은 `localStorage`에 저장됩니다. 새로고침하면 저장된 단계에서 이어서 진행하고 이미 확정한 참가자나 미션을 다시 추첨하지 않습니다. 이 정보는 진행 브라우저 한 곳에만 저장되므로 여러 기기에서 공유되지는 않습니다. 저장소 접근이 차단된 브라우저에서는 현재 탭 메모리에서 실행합니다.

새 데이터는 `everland-mt-draw-v2` 키를 사용합니다. 이전 16명·4팀 형식의 `everland-event-tickets-v1` 저장값은 새 구성과 호환되지 않아 초기 실행 시 제거합니다. 새 참가자 명단은 처음부터 `JW`를 제외하므로 예전 저장 데이터가 참가자 풀에 섞이지 않습니다.

사다리 구조와 결과 계산은 [ladder.js](ladder.js)에 있습니다. 한 높이에서 서로 겹치지 않는 인접 세로줄만 연결하고, 각 높이의 연결을 따라가며 도착 위치를 계산합니다. 이 인접 교환 구조는 출발 위치와 도착 위치 사이에 일대일 순열을 만들기 때문에 각 미션에는 정확히 한 명이 도착합니다. 화면의 선과 마커는 이 계산 결과를 그대로 그립니다.

## 검증

```sh
node --test tests/raffle.test.js
python3 -m http.server 8000
```

테스트는 15명 명단, 고정 팀 제외, 난이도별 놀이기구 중복 방지, 순차 참가자 배정과 새로고침 복원, 미션 수와 스페셜 미션 연결, 사다리 비충돌·일대일 매칭, 팀장 선정 및 재선택 안정성을 확인합니다.

## 실행과 GitHub Pages

빌드 단계나 런타임 라이브러리 없이 `index.html`을 정적 호스팅에 배포할 수 있습니다. GitHub 저장소의 **Settings → Pages**에서 `main` 브랜치와 저장소 루트(`/`)를 배포 대상으로 지정하면 됩니다.

```sh
python3 -m http.server 8000
```

브라우저에서 `http://localhost:8000`을 열어 진행합니다. 사용자가 효과음을 직접 켤 수 있고, 기기의 동작 줄이기 설정도 반영합니다. 기존 모션 참고 자료는 [REFERENCES.md](REFERENCES.md)에 정리되어 있습니다.
