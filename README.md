# 에버랜드 MT 블라인드 추첨 시스템

15명의 참가자를 세 팀으로 나누고 놀이기구, 블라인드 미션, 사다리 결과를 확정하는 정적 웹 앱입니다. 공개 진행 화면에는 미션 문구와 팀장 여부를 표시하지 않으며, 운영자 출력 페이지에서 참가자별 실물 티켓을 확인하고 저장합니다.

## 팀 구성과 참가자

| 팀 | 난이도 | 인원 | 놀이기구 배정 |
| --- | --- | ---: | --- |
| 상 난이도 1팀 | 상 | 5명 무작위 추첨 | 상 난이도 목록에서 추첨 |
| 상 난이도 2팀 | 상 | 5명 무작위 추첨 | 상 난이도 목록에서 추첨 |
| 중 난이도 1팀 | 중 | BJ, MYJ, JT, KW, CYJ 사전 확정 | 중 난이도 목록에서 추첨 |

참가자는 `KMK`, `MJ`, `MH`, `BJ`, `SB`, `MYJ`, `PMK`, `SI`, `JT`, `KW`, `SH`, `HW`, `SW`, `CYJ`, `SM`입니다. `JW`는 포함하지 않습니다. 상 난이도 팀은 이름 추첨을 한 명씩 진행하며, 같은 난이도의 놀이기구는 중복되지 않습니다.

## 진행과 블라인드 배정

1. 난이도에 맞는 놀이기구를 기존 원통형 룰렛과 연출로 추첨합니다.
2. 상 난이도 팀은 참가자 다섯 명을 순차 추첨하고, 중 난이도 팀은 고정 참가자 명단을 사용합니다.
3. 각 팀은 해당 놀이기구의 스페셜 미션 한 개와 서로 다른 일반 미션 네 개를 뽑습니다. 다섯 미션의 위치를 섞으므로 스페셜 미션이 특정 사다리 슬롯에 고정되지 않습니다.
4. 공개 미션 카드와 사다리 하단에는 `MISSION A`부터 `MISSION E`까지만 표시합니다. 카드의 색·아이콘·크기는 같고, 결과 화면은 참가자와 슬롯의 연결만 보여줍니다.
5. 스페셜 미션에 연결된 참가자는 내부 상태에서 팀장이 됩니다. 공개 진행 중에는 미션 유형과 팀장 여부를 표시하지 않습니다.
6. 모든 팀이 끝나면 공개 화면에는 세 팀의 놀이기구와 블라인드 슬롯 배정만 남습니다.

미션 데이터는 [event-data.js](event-data.js)에 있습니다. 스페셜 미션 4개와 일반 미션 18개를 설정 구조로 보관하고, 한 팀 안에서는 일반 미션이나 미션 슬롯이 중복되지 않습니다.

## 운영자 티켓

운영자 출력 페이지는 [operator.html](operator.html)입니다. 공개 진행 흐름에는 이 페이지로 가는 버튼을 두지 않았습니다. 직접 주소로 열면 운영자 확인 화면을 거칩니다.

- 같은 브라우저의 완료된 추첨 결과를 자동으로 불러옵니다.
- 다른 운영자 기기에서는 공개 최종 화면의 **운영자 기기로 전달할 티켓 데이터 저장** 버튼으로 내려받은 JSON을 불러옵니다.
- 티켓 한 장에는 한 참가자의 미션만 표시하며, 팀·놀이기구·난이도·이니셜·미션 유형·팀장 표시·고유 번호와 사회공헌단 로고가 들어갑니다.
- 참가자별 PNG 저장 및 A6 가로형 인쇄를 지원합니다. PNG는 1748 × 1240 픽셀로 렌더링합니다.
- 전체 15장 PNG를 ZIP으로 저장하거나, A4 가로 한 페이지에 네 장씩 인쇄할 수 있습니다. 총 네 페이지가 만들어지고 마지막 페이지에는 세 장이 배치됩니다. 브라우저 인쇄 대화상자에서 PDF로 저장할 수도 있습니다.
- PNG 및 ZIP 파일명에는 팀 번호와 참가자 이니셜만 사용합니다.

로고 원본은 [assets/social-contribution-logo.png](assets/social-contribution-logo.png)에 보관하며 PNG 인쇄·저장에 포함합니다.

## 상태 저장과 비공개 한계

추첨 진행 상태, 미션 연결, 사다리, 팀장, 티켓 생성 여부는 브라우저의 `localStorage`에 저장됩니다. 같은 브라우저 프로필의 공개 화면과 운영자 페이지는 이 상태를 공유합니다. 다른 기기에서는 운영자 JSON 파일을 안전하게 전달해 불러옵니다.

새 상태는 `everland-mt-draw-v3` 키를 사용합니다. 기존 v2 상태가 있으면 놀이기구와 참가자 배정은 유지하지만, 새 미션 목록을 적용하기 위해 이전 미션·사다리 결과는 다시 추첨해야 합니다. 예전 16명·4팀 형식의 `everland-event-tickets-v1` 상태는 제거됩니다.

이 앱은 정적 웹 사이트이며 기존 인증 시스템이나 백엔드가 없습니다. 따라서 화면에서 미션을 숨기고 운영자 페이지를 분리하더라도, 저장된 추첨 상태나 공개 저장소의 소스에 접근할 수 있는 사람에게 실제 기밀성을 보장하지는 않습니다. 운영자 JSON에는 모든 미션과 팀장 정보가 들어가므로 운영자에게만 전달해야 합니다. 강한 접근 제어가 필요하면 서버 인증과 서버 측 비밀 저장이 필요합니다.

## 로컬 실행

Node.js 테스트와 정적 서버 실행:

```sh
node --test tests/raffle.test.js
python3 -m http.server 8000
```

공개 추첨은 `http://localhost:8000/`, 운영자 출력은 `http://localhost:8000/operator.html`에서 엽니다. 프로젝트에는 빌드 단계나 외부 런타임 라이브러리가 없습니다. 기존 사다리 생성 및 경로 계산은 [ladder.js](ladder.js)에 유지합니다.

## 검증 범위

자동화 테스트는 참가자 명단, 새 미션 풀, 놀이기구 중복 방지, v2 상태 이전, 블라인드 상태 반환, 스페셜 미션 슬롯 무작위화, 사다리 순열, 팀장 배정, 결과 복원 및 티켓 생성 상태를 확인합니다.
